# GlassNX v0.1 — uLaunch integration preview

This branch retains uLaunch 1.2.6's native uSystem, uLoader, uMenu and uManager, with an initial GlassNX presentation layer. Upstream license and credits remain unchanged.

- Pastel Dream wallpaper, translucent panels and luminous selection ring generated offline into the bundled default theme at build time. Texture dimensions are inherited from upstream; custom installed themes may override the default.
- Restyled native lock screen, dialogs, quick menu and notification toasts.
- Notification history (24 entries, newest first, session-only) accessed from the ZL/ZR quick menu. Existing uLaunch notification sources are retained. Low battery notice at 15%, rearmed at 25% or charging. No fake events.
- Existing game and homebrew launching, suspend/resume, folders and system settings remain upstream.

## Build
Use the existing GitHub Actions workflow for this branch. The expected artifact is SdOut.zip. Local build follows the upstream devkitPro instructions; `make umenu` now invokes the standard-library Python asset generator before packing romfs.

## Testing / recovery
This is an unverified integration preview, not the final six-screen design or a verified NRO. Test only after CI succeeds. Back up the SD card and existing HOME replacement. Prefer offline emuMMC for initial validation; online use of any HOME replacement carries ban risk. If boot or menu fails, restore the original HOME override using uManager or remove only the replacement `atmosphere/contents/0100000000001000/exefs.nsp` after powering off, preserving other files and themes. Restore any prior backup if applicable. Do not install on an unmodified console.

## Next milestones
Dedicated six-page navigation and actual game artwork dashboard; reusable dynamic GPU glass material and transition animations; durable notification service and homebrew API; real brightness/volume and optional compatible performance controls. No clocks are changed by this preview. Target 720p/60fps requires device measurements. Original mockups remain the acceptance target, not the current visual result.

## v0.2 — native shell layout pass
The default main menu now renders a separate controller/touch-driven GlassShell over uLaunch's native entry data. L/R switches Home, Library, Apps and Settings; ZL/ZR opens Control Center, + opens Notifications, A selects, B returns Home, Y filters, and Minus switches to the legacy grid. In the legacy grid hold Plus and press Minus to restore GlassShell. Existing launch handlers, title suspension and system services are reused. Library and app lists are scoped to the active uLaunch folder; manage folders/entries in legacy. Theme and glass controls are session-only. Lock screen uses a large clock and latest real session alert. No fake statistics, no clock changes. Brightness, volume, temperature, favorites, search, persistent preferences, banner art and GPU refraction remain unfinished. Native compile and hardware verification are required.

### v0.2 rendering and hardware follow-up
Cached half-resolution textured glass bevels and reflective edges replace flat card fills. The GPU composites the cached surfaces, not live backdrop refraction. Home and Control Center query actual battery, SD free space and SoC temperature; brightness and master volume use libnx with service-result checks and display Unavailable if unsupported. Controller left/right adjusts a focused slider, up/down changes selection. Touch adjusts slider position. Brightness is clamped to at least 10%. No CPU/GPU/RAM clocks are changed. Service behavior and visual performance still need hardware confirmation.

## v0.5 — independent boot-time installation

The existing uLaunch installation/config is not needed. The installer is GlassNXManager.nro with a disabled upstream updater. ## v0.10 — stability and one-package updater
Resume RPC is gated and sent once per transition; failure is reported instead of asserting. Termination failure is handled without falsely resetting suspended state. Renderer releases its own caches before title transitions, caps glass texture payload to 6 MiB, uses smaller textures, throttles metrics to 8–30 seconds and suppresses optional polling, animation, custom hero art and textured geometry while a title is suspended or Safe Mode is enabled. Safe Mode is persistent via /glassnx/safe-mode, accessible in Settings > About or the manager; it is not automatic crash detection. No claim of fixed Atmosphere crashes without crash reports and device tests. Profile selector and glass material are refined.

First install the complete v0.10 package manually. For later releases transfer the inner complete GlassNX release ZIP as /glassnx/update.zip (e.g. with SwitchDrop), close all games, open GlassNX Manager and select Update / Recovery / Safe Mode > Install ZIP. Manager extracts only a fixed allowlist to staging, checks CRC and sizes, backs up live files, writes a recovery journal, disables the active HOME override before replacing binaries, and reinstates it only after verification. Preferences, saves, themes, and unrelated Atmosphere files are not replaced. A separate GlassNXRecovery.nro is copied before mutation. Restore previous version uses the retained backup and journal. Keep power connected and back up the SD externally: FAT operations are not a truly atomic multi-file transaction. Do not install arbitrary ZIPs; CRC is integrity, not authenticity. No network downloader or automatic updates yet; only the user-approved local package workflow. One update in progress at a time. Test interrupted update and recovery on spare media before relying on it.

### Direct artwork importer (experimental)
GlassNX Manager > SteamGridDB artwork imports user-selected JPEG hero art directly over HTTPS, using an exported title list. Requires /glassnx/steamgriddb.key (own 32-hex-character API key) and /glassnx/cacert.pem (trusted CA bundle from https://curl.se/docs/caextract.html). Key is sent only to the API host, not CDN; no insecure TLS, no redirects, bounded timeouts/responses. The native importer only accepts JPEG up to 1920x1080 and provides a list rather than image previews. The desktop importer remains available for other formats. No networking is added to HOME or Core. Live API, TLS and Switch device tests pending. Discord presence is still deferred; the supported local RPC requires a desktop or supported mobile client, and additional sysmodules are not bundled.

Native system tiles (Mii, browser, profile, settings, themes, controllers, album, amiibo and folders) now render original glass glyphs rather than the upstream square artwork. Installed games/homebrew keep their actual app artwork. Home system and storage widgets are touch shortcuts. This does not replace every icon inside external Nintendo applets.

### Optional Discord desktop bridge
The release includes glassnx_presence.py, a desktop client for the existing SwitchPresence-Rewritten TCP wire format (packed little-endian u64 magic, u64 title ID, 612-byte name). Requires a separately installed compatible SwitchPresence-Rewritten server, a trusted local network, running desktop Discord and a user-created Discord application ID. No sysmodule is bundled or added to Core. The bridge handles partial TCP reads, disconnect timeouts, activity clearing and rate-limited RPC updates. Existing server reports running process, not foreground/suspended status, so activity may remain during HOME suspension; clear on disconnect/home with no process. Host protocol tests run in CI. Live Discord and Switch compatibility are unverified. Hardware QA checklist included. Do not use the optional sysmodule until baseline stability passes.

## Artwork normalization and featured glass

SteamGridDB Cover imports now require a decoded center square of at least 1024×1024, exporting PNG data to `.cover` (512×512, shared by Home/Library/Apps) and `.cover1024` (1024×1024). Hero imports use exactly 1130×405 (226:81), matching the featured artwork rectangle. Manager and desktop imports use the same hero dimensions and `.hero` destination. No stretching or enlargement is permitted. Existing bounded downloads, TLS restrictions, explicit selection, Safe Mode and suspended-game guards remain. PNG writes use temporary files and rename; the 512 asset remains the active tile if the second export fails. Existing imported assets are retained until replaced.

The featured card now has a smaller rounded glass information panel, lighter tint and white rim, with title, status, Play/Resume and Game options. Suspended games retain a separate Close control. Picker previews show the normalized composition, source dimensions, asset type and output rules; successful imports display a specific toast. Resolution/decode checks reject undersized or malformed sources; subjective compression/blur quality is left to the visible preview. Console visual/performance testing and live authenticated SteamGridDB testing remain necessary.
